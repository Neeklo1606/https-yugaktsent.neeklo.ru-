## Шахматка
- **Причина «кривой» шахматки**: стояки угадывались по площадям соседних этажей, и одна и та же
  квартира прыгала по столбцам (1к 40,7 м² в «На высоком берегу» — в столбцах 1, 7, 8, 9, 10, 11).
- **Теперь стояки берутся из данных застройщика** (`packages/shared/src/chessboard/risers.ts`):
  1. номер окна в имени файла планировки ССК (`…_s4_p4_f2-9_n02.png` → секция 4, окно 2) — 12 из 16 ЖК;
  2. номер «этаж + порядковый» (1001…1021) — Николай 1, Eden;
  3. иначе прежний алгоритм. Проверено на всех 16 ЖК: ни одна квартира не теряется.
- Секции одного дома (Борский, Сердце, Фонтаны…) идут группами с подписью «Секция 3» и зазором.
  Пропущенные номера окон внутри секции дорисовываются пустыми — дом выглядит целым.
- Вид: ячейка 80×52 (телефон 70×48), крупно комнатность, площадь, цена «11,8 млн».
  Проданная — серая штриховка, «нет в продаже» — пунктир, бронь — жёлтая. Легенда с отдельными счётчиками.
- Телефон: «Дом» и «Секция» — два списка в одну строку, легенда под сеткой; сетка видна сразу.
- Корпус с названием «3» подписывается «Корпус 3».
- Для выкладки нужен **API** (сетку строит сервер): пересобрать `packages/shared` и перезапустить API.

## Описания ЖК
- `deploy/yugaktsent/content/complex-descriptions.json`: 16 ЖК, 3 абзаца своими словами (650–880 знаков),
  подзаголовок, 4–5 фактических преимуществ, застройщик, адрес, источники и надёжность (high/medium/low).
  Цен в текстах нет. Николай 1 — надёжность low (застройщик и адрес не подтверждены) — их не ставим.

  запись через Admin API; заполняет только пустое, правки менеджера не трогает). Координаты не ставим.
- Карточка ЖК: подзаголовок, абзацы описания (ширина строки ≤78 знаков), преимущества галочками.
  Застройщик текстом, если его нет в справочнике. «Корпусов 42» → «Домов 7 · Секций 42». Дубль «Застройщик» убран.
- Админка ЖК: поля «Подзаголовок», «Преимущества (по одному в строке)», «Застройщик текстом».
