## 4. План разворачивания

### Этап 0. Подготовка (до сервера)
1. Заказать VPS (раздел 3), добавить свой SSH-ключ, закрыть вход по паролю.
2. Решить домен. Если остаётся `yugaktsent.neeklo.ru` — DNS у `neeklo.ru`; если новый — купить/настроить.
3. Снизить TTL A-записи домена до 300 с (если DNS-зона ещё доступна).
4. Собрать у заказчика: ссылки на все фиды Profitbase, телефоны/адрес/соцсети, токен Telegram-бота и ID чата, ключ Яндекс.Карт, фото/обложки ЖК.

### Этап 1. Сервер (~1 час)
1. A-запись домена → IP нового сервера (нужна для сертификата Let's Encrypt).
2. Репозиторий приватный: создать на сервере deploy-ключ и добавить его в GitHub только на чтение (команды — `deploy/yugaktsent/README.md`, раздел «Deploy-ключ»).
3. Под root:
   ```bash
   export SITE_DOMAIN=yugaktsent.neeklo.ru CERTBOT_EMAIL=<почта>
   git clone git@github.com:letoceiling-coder/https-yugaktsent.neeklo.ru-.git /var/www/yugaktsent-lg
   bash /var/www/yugaktsent-lg/deploy/yugaktsent/provision-server.sh
   ```
   Скрипт ставит Node 22, pnpm, PostgreSQL 16 + PostGIS, Redis, nginx + image_filter, certbot, ufw (22/80/443), swap, cron бэкапа; создаёт БД, `.env` с **новыми** секретами (JWT, БД, ключ шифрования, пароль админа), собирает и запускает всё, выпускает сертификат.
4. Проверить `.env`: `FEEDS_JSON`, `PUBLIC_SITE_URL`, `CORS_ORIGINS`. Пароль админа: `grep LG_ADMIN_PASSWORD /var/www/yugaktsent-lg/.env` — сохранить в менеджер паролей.

### Этап 2. Данные (~0,5–1 день, зависит от заказчика)
1. Дождаться первой синхронизации фидов (лог `/var/log/yugaktsent-lg/profitbase-sync-out.log`) или нажать «Синхронизировать сейчас» в админке.
2. Добавить в админке «Фиды» потерянные фиды (Eden, Sun Garden и др.), запустить синхронизацию.
3. Админка → «Настройки»: контакты, соцсети, токен Telegram-бота, ID чата, ключ Яндекс.Карт, SEO-тексты.
4. Ручные правки ЖК: обложки, адреса, координаты, описания. Новости.
5. Завести пользователей админки (менеджеры) с новыми паролями.
6. **Повторно запустить `deploy-full.sh`** — тогда пререндерятся страницы всех ЖК (на первом деплое API ещё пуст).

### Этап 3. Проверка
- [ ] `curl -sI https://<домен>/` → 200, HSTS на месте
- [ ] `curl -s https://<домен>/api/v1/health` → ok
- [ ] `https://<домен>/docs` → 404; `POST /api/v1/auth/register` → 404
- [ ] Фото ЖК идут через `/img/800/...`, заголовок `X-Img-Cache`
- [ ] Каталог, карта, страница ЖК, шахматка, PDF
- [ ] Тестовая заявка доходит в админку и в Telegram
- [ ] Вход в админку, синхронизация фида из админки
- [ ] `sitemap-index.xml`, `robots.txt` с правильным доменом
- [ ] QA-скрипт: `node deploy/yugaktsent/qa/browser-qa.mjs` против нового домена
- [ ] `systemctl status yugaktsent-api yugaktsent-profitbase-sync`, `df -h` (запас диска)

### Этап 4. Защита от повторения (сразу после запуска)
1. **Бэкап вне сервера.** Cron делает `pg_dump` каждую ночь в `/root/db-backups`. Создать `/etc/yugaktsent/backup.env` с `BACKUP_RSYNC_TARGET=user@host:/path` или `BACKUP_RCLONE_TARGET=s3remote:bucket/yug` (Яндекс Object Storage / Selectel S3). Без этого бэкап умрёт вместе с сервером, как в этот раз.
2. Бэкап `/srv/yugaktsent-lg/uploads` (ручные загрузки) туда же, раз в сутки `rclone sync`.
3. Снапшоты у провайдера — раз в сутки.
4. Внешний uptime-монитор на `/` и `/api/v1/health` (UptimeRobot / Яндекс Мониторинг) с уведомлением в Telegram.
5. Мониторинг диска: алерт при > 80 %.

## 5. Секреты — сменить все

Старые секреты считаем скомпрометированными (сервер у хостинга, часть была в публичном репозитории):
- Пароль `admin@yugaktsent.ru` — лежал в `deploy/yugaktsent/env.example` публичного репо; убран 07.11, но остался в истории git. Новый генерирует bootstrap.
- JWT-секреты, пароль БД — генерируются заново.
- **Токен Telegram-бота** — перевыпустить в @BotFather (`/revoke`), старый был в БД на сервере.
- Ссылки экспорта Profitbase с токенами — лежат в публичном репо (`env.example`, `update-feeds-env.mjs`). Репозиторий закрываем, но ссылки уже были публичными — попросить застройщиков/Profitbase перевыпустить их, новые хранить только в `.env` / админке.
- Ключ Яндекс.Карт — ограничить по домену (HTTP Referer) в кабинете разработчика.
