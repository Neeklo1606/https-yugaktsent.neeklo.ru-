**Что делать (по эффекту):**
1. Метрика — грузить после `load` + простоя или первого действия, и только после согласия на cookie. Сейчас её вставляет панель
   хостинга (`/etc/nginx/hostcare/metrika-map.conf`) — на сервере заказчика подключаем сами из админки (номер счётчика — настройка).
2. Ресайзер картинок `/img/` — отдавать WebP (AVIF) по `Accept`; планировки `bx.sskuban.ru` — через ресайзер (нужно OK на nginx).
3. API: кэш ответов «похожие/рядом/поиск/цены по комнатам» (in-memory 60–300 с), индексы под эти запросы; цель p95 ≤ 300 мс.
4. Главная на телефоне: отложить гидрацию нижних блоков (карусели, карта) до прокрутки; убрать лишние запросы на старте.
5. brotli в nginx (на новом сервере), HTTP/2 уже есть.
6. Полевые метрики: web-vitals → Метрика (параметры визита) — видеть реальные LCP/INP посетителей.

**Стандарт анимаций сайта (принят 21.11):**
- появление блоков при прокрутке — `Reveal`: подъём 14 px + прозрачность, 550 мс, `cubic-bezier(.2,.7,.2,1)`, один раз;
- наведение на карточку — подъём 2 px + тень, 200 мс; фото в карточке — лёгкое приближение 3 %, 700 мс;
- кнопки и вкладки — цвет/фон 150 мс, полоска активной вкладки — 200 мс;
- никаких анимаций ширины/высоты/top (только transform/opacity), автозапуска видео и параллакса;
- при системной настройке «уменьшить движение» всё появляется сразу.

## 9. Переезд на домен заказчика (чек-лист)

1. Сервер заказчика: Node 22, PostgreSQL, nginx (brotli), certbot; перенос базы дампом, `uploads/`.
2. Переменные: `PUBLIC_SITE_URL`, CORS, адреса в sitemap/canonical/JSON-LD — новый домен; пересборка и пререндер.
3. DNS → SSL → проверка на временном адресе → переключение.
4. 301 со старого адреса на новый (все пути), sitemap и robots — с новым доменом.
5. Яндекс.Вебмастер и Search Console: подтверждение, «переезд сайта», отправка sitemap.
6. Метрика — новый счётчик/цель «заявка», отложенная загрузка после согласия.
7. Почта домена: SPF, DKIM, DMARC (если заявки уходят письмом).
8. Сторож API, ежедневный бэкап с копией вне сервера, ротация логов.
