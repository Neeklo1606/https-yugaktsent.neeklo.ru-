## 1. Что увидел на боевом сайте (взгляд продуктового дизайнера)

Проход: мобильная версия 375 px — главная, каталог, страница ЖК.

**Доверие и данные: это бьёт по конверсии сильнее всего**
1. Почти у всех квартир заглушка «Фото отсутствует», у части ЖК тоже. Для агентства недвижимости это главный убийца доверия.
2. В каталоге показывается Eden «1-к от 7,5 млн», а на странице ЖК «от 8,5 млн». Цена «от» расходится.
3. Страница ЖК: «Описание появится позже», «Адрес —», «Район —», «Метро —». По ТЗ метро быть не должно, а пустые строки нужно скрывать.
4. Заголовок каталога: «5 200 объектов • 5 жилых комплексов», «Актуальная недвижимость по всей России», «5 загружено • всего в каталоге 5». Это служебный текст, а не продуктовый.
5. Поиск с подсказкой «Метро, район, ЖК…» противоречит ТЗ.
6. Сортировка по умолчанию «Название, А→Я» человеку ничего не даёт. Лучше «Сначала популярные» или «Сначала дешевле».
7. Блок карты на главной — пустое поле с точками: не задан ключ Яндекс.Карт.

**Конверсия**
8. Нет чат-виджета и кнопки Telegram в липкой панели объекта. По ТЗ оба обязательны.
9. Лид-форма одинаковая везде. На ЖК и объекте форма должна знать, о каком объекте речь: «Узнать цену на 2-к в Eden», а не «Получить консультацию».
10. Нет быстрых действий «Позвонить / Написать в Telegram / MAX» в шапке на мобильном: в шапке есть телефон, мессенджеров нет.
11. «Избранное» у гостя на карточке ЖК уводит на `/login`. Это видимый сбой.

**Структура**
12. Нет блока «Купить объект» и YouTube-видео о компании (оба есть в ТЗ).
13. Нет «Хода строительства» на странице ЖК.
14. Квиз «Подберём объект» — хорошая находка, его стоит поднять выше и связать с CRM.

## 6. Процесс работы

1. Каждая задача — отдельная ветка `feat/<ID>-...` → PR в `main` → ревью → деплой.
2. Перед каждым деплоем — бэкап БД. После деплоя — smoke-проверка: главная, каталог, ЖК, заявка, админка.
3. Локальная разработка: фронт ходит в **боевой** API (`.env.local`), поэтому в локальной админке **ничего не сохранять**. Для задач в админке и API поднять локальную БД (`docker-compose.yml` + `scripts/restore-prod-db-local.ps1`) или отдельный staging.
4. Статус задач — по ID из бэклога в этом документе, отмечать галочки в чек-листе.
